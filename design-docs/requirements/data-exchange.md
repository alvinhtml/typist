# 生词本与补充词库导入导出

更新时间：2026-10-30。状态：以下规则已确认，阶段 4 已实现并完成本机自动检查；系统对话框与跨平台人工验收待补，见 ../validation/phase4-report.md。

## 1. 入口与文件内容

- 设置中心分别提供生词本、补充词库的导入导出入口。
- 两类文件均使用 CSV。生词本包含文字、编码；补充词库包含文字、编码、分类。
- 同一文字有多个编码时，每个文字与编码组合分别表达，不丢失编码。
- 不携带学习进度，包括连续正确次数、错误次数、当前练习组等。
- 补充词库仅导出用户补充数据，不修改或导出为对内置 `data` 的覆盖文件。
- 生词本列为 `word,code`，补充词库列为 `word,code,level`；`level` 为 1～5，分别对应一级至四级及词组。
- 导出 UTF-8 BOM，导入接受有或无 BOM 的 UTF-8，不猜测其他字符编码；每行一个编码组合。

## 2. 统一去重与合并

- 生词本、补充词库及托盘文本添加统一按“文字＋编码”去重；完全相同则忽略，同文字不同编码保留。
- 此规则取代此前“生词按文字去重、文件重复项以导入内容为准”的约定，不覆盖已有编码。
- 导入与本地数据合并，保留本地独有条目，不因导入而删除。
- 已有条目保留本机学习进度，新条目从未学习状态开始。
- 补充词库去重时同时检查内置数据，不重复添加内置已有的文字与编码组合。
- 生词列表按文字聚合展示全部编码，展开可单独删除编码；同课程按文字保存练习进度，不同课程独立。
- 相同文字与编码但分类不同，导入时忽略重复，保留本机已有分类；文件内重复保留首个有效分类，并在反馈中提示分类冲突。

## 3. 迁移与词库校验

- 两台电脑之间迁移时，先导入补充词库，再导入生词本。
- 生词本导入的文字与编码必须匹配本机内置与补充词库的合并结果；无法匹配的条目跳过并提示原因。
- 生词本导入不自动创建补充词库条目，不绕过词库识别限制。
- 补充词库导入后，其有效条目参与识别、取码及对应课程练习。

## 4. 异常与结果反馈

- 缺少必要列、文件无法解析等文件结构错误：整份不导入，提示原因。
- 个别行缺字、缺码或分类不合法等行级错误：跳过该行，其余有效行正常合并。
- 完成后显示新增、重复忽略和失败数量，可查看失败行及原因；不设置覆盖更新数量。
- 文件内重复与本地已有重复均适用统一去重规则。
- 空白行及额外列忽略，每行一个编码；补充条目输入规范见 [补充词库需求](supplemental-dictionary.md)，生词组合仍需匹配词库。
- 新增和重复按文字与编码组合处理，分类冲突计入重复忽略并提示原因。

## 5. 后续验收检查点

以下为待执行检查，不代表验证通过：

- 两类 CSV 均可导出并在另一台电脑导入，字段符合各自职责，不包含学习进度。
- 重复导入不会增加相同文字与编码组合，同文字不同编码仍保留。
- 合并保留本地独有条目及已有学习进度，新条目为未学习状态。
- 补充词库先导入后，其对应生词能通过文字与编码匹配；未匹配条目被跳过并说明原因。
- 文件结构错误不产生部分导入；行级错误不阻止其他有效行合并，反馈数量和原因可核对。
