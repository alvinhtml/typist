# 阶段 4：设置、CSV 与跨窗口闭环

2026-10-31。状态：用户已确认实施方案；实现与本机自动检查已交付，系统文件对话框及跨平台人工验收待补。详见 test-results/phase4-report.md。

## 目标与边界

依据 roadmap 阶段 4、requirements/data-exchange.md、requirements/settings-and-session.md 和 architecture/api.md。复用 SQLite v1、版本检查、请求幂等、最终词库同步与提交后广播；不迁移数据库，不改内置 data，不开发游戏。

## 实施顺序

1. 实现独立 CSV 解析与序列化：严格 UTF-8、可选 BOM、引号转义与换行、必需表头、空行及额外列；结构错误整份拒绝，行错误保留行号和原因。导出固定字段及 UTF-8 BOM，不包含学习数据。
2. 细化并实现固定 importCsv/exportCsv bridge，kind 仅允许 vocabulary/supplemental；路径留在主进程，由系统文件对话框选择，取消返回 CANCELLED。导入沿用 Write 的 requestId/expectedRevision，并在选择文件后检查版本，避免对话框期间覆盖其他窗口修改。
3. 全文件预解析后单事务合并；复用组合去重和最终词库校验，重复分类保留本地或首个有效值；返回新增、重复、失败及行级原因。保留学习进度，事务成功后统一广播。
4. 设置中心添加两类导入导出入口与结果明细；说明迁移顺序。检查设置仅下次开局生效、双窗口同步、活动题变更取消和确认取消后的现场。

## 验证与完成条件

- 确定性测试覆盖 BOM/无 BOM、非法 UTF-8、引号和换行、缺列、非法行、跨分类重复、同字多码、重复导入、往返交换及事务失败不部分写入。
- 运行类型检查、构建、现有业务测试及 Electron 基础/业务/练习回归，补双窗口 CSV 集成场景。
- 对照基线确认内置 CSV 未变，检查学习记录不被导入覆盖。
- 系统文件对话框及 Windows 未实测项单独记录；自动检查不代替人工平台验收。
- 完成后更新接口、需求实现状态、current、roadmap 和阶段报告；未经验证不得标记整体验收通过。
