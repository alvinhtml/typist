# 界面改版实施文档

## 1. 已确认要求

- 暖白背景、深墨文字、深绿色强调 #237A60（用户在设计稿中确认取代原蓝色），提升设计感，不只是换色。
- 无侧边栏，启动显示居中功能菜单，点击进入各页面。
- 中央以练习文字为主；课程、计时、暂停等操作弱化放顶部，实时成绩放底部。
- 练习不出现明显的表单输入框。
- 首页菜单鼠标移入及点击具有精致、鲜明的动画效果。
- 用户反馈编码整改实测符合预期；不扩大为未测试平台也通过。

## 2. 已确认布局与动效（用户确认「静墨」设计稿）

### 首页

- 中央以分级练习、生词练习、打字游戏为主要入口，下方轻量呈现生词本、添加文本、设置。
- 顶部小型品牌，底部简短离线状态，不堆大标题及说明卡片；托盘文本窗口仍可打开。
- 生词练习复用已有课程模型及进度，不创建独立重复数据。

### 练习页

- 顶部控制条：返回首页、课程、时长、剩余时间、暂停/继续、结束；按会话状态启用控件。
- 中央：待练文字/词组、错误编码提示、正误对齐反馈，以及实时编码与轻量光标。用留白和细下划线等突出当前题，弱化每题厚重卡片。
- 底部成绩条：速度、正确率、已答题数、覆盖/熟练等，避免重复大标题。
- 上一轮作答默认收起；展开或窄窗口时合理滚动，不能覆盖题目、输入反馈或按钮。
- 顶中底采用页面分区，不通过悬浮条遮住内容；长词组、多编码、罕见字和缩放均需检查。
- 展示未开始、倒计时、运行、暂停、空课程、错误恢复和结束成绩状态，不只设计运行态。
- 生词和设置仍采用适合管理的列表/表单，只统一视觉，不强行垂直居中。

### 无明显输入框

- 弱化外观不等于删除输入能力与焦点语义；优先复用编码适配器，调整控件样式和焦点管理，具体方法需验证。
- 实时显示编码缓冲和光标，运行/失焦/暂停状态清晰；开始和恢复后可直接输入，无需额外点击大输入框。
- 顶部按钮、下拉框、设置和托盘文本框保留键盘操作，不被练习监听误截获；保留可见焦点与键盘可达性。
- 不使用全局键盘钩子，不用无边界全页监听替代输入控件，防止按钮空格误跳题、快捷键误作答或中文上屏重新参与判定。

### 菜单动效

- 移入候选：轻微上浮、深绿色边缘高亮、柔和光晕，图标小幅位移，局部光晕跟随鼠标。
- 点击候选：短暂下压及点击位置波纹，然后过渡进入页面；离开平滑复位。
- 主入口更鲜明，管理入口更轻，动效集中首页，练习保持安静。
- 键盘聚焦提供对应反馈，支持减少动态效果；点击不等待长动画，不重复触发导航。
- 正式视觉采用系统字体、暖白 #faf9f5、深墨 #202b38、强调绿 #237A60；首页上浮 5px、按下缩放 98%，波纹 450ms，导航不等待动画且防重复触发；减少动态效果时禁用位移和波纹。

## 3. 推荐执行顺序

1. 先制作一套首页与练习页高保真稿，包括正常/窄窗口、练习运行/暂停、菜单默认/移入/按下状态。动效另以短交互样例验证，不用静态图声称动画已验证。
2. 用户确认入口主次、字体间距、编码位置、顶底布局及动效后，再整体修改正式页面；不需要一开始制作多套完整方案。
3. 建立统一视觉变量、公共页面壳、首页及返回导航，再改练习布局和输入外观，最后统一生词、设置和托盘小窗口样式。
4. 游戏仅保留入口和未实现状态，不提前开发阶段 5 或决定未确认的编码匹配规则。
5. 截图与交互检查、业务回归完成后出具改版报告，更新需求及状态。

先设计后实现是本次流程建议；具体稿件未经确认不能自动视为已确认需求。

## 4. 代码影响与约束

- 主要涉及 src/renderer/App.vue、PracticePanel.vue、VocabularyPanel.vue、style.css；按需抽取展示组件，不改写无关业务。
- 默认页改首页，取消侧边栏；练习实例保持：返回首页暂停保留现场，再进练习手动继续。切课及重开仍沿用现有确认。
- 编码提交、分组复习、事务保存、学习进度、统计、托盘生命周期和跨窗口同步保持现有规则。
- smoke 若依赖菜单/输入 DOM，更新定位同时保留业务断言，不删检查制造通过。
- 不默认增加依赖、网络字体或大型动效库；原型隔离制作，正式工程仍使用 Electron/Vue。

## 5. 验收

- 启动菜单居中，无侧栏，全部入口、返回与托盘路径可用。
