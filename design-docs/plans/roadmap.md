# 分阶段开发计划

更新时间：2026-10-30。状态：阶段 0 设计与最小原型已交付，验证结论和限制见 validation/phase0-report.md；阶段 1～6 未开始。

## 1. 依据与执行边界

- 产品范围以 [项目概览](../requirements/overview.md) 为准，具体行为引用模块需求，不在计划中重新定义。
- 技术栈已确认 Electron、Vue 3、TypeScript；具体方案状态见 [技术约束](../architecture/overview.md)。
- 当前有文档、内置词库及隔离验证原型，尚无正式业务工程；旧项目功能描述不视为已实现。
- 原计划编写边界已由 2026-10-30 用户指令更新：允许阶段 0 设计及最小验证原型；重要技术决策先确认，禁止提前进入阶段 1～6，内置 data 不变。
- 顺序为 0 → 1 → 2 → 3 → 4 → 5 → 6。每阶段完成相关检查后才能宣称阶段通过。
- 无排期承诺；工时应在阶段 0 选型、输入验证及原型后评估，避免未经验证的估算。
- 不纳入云同步、历史成绩趋势、排行榜、闯关或整套学习进度备份。

## 2. 阶段总览

| 阶段 | 目标 | 主要交付 | 前置依赖 |
| --- | --- | --- | --- |
| 0 | 技术设计与风险验证 | 架构、数据与接口约定，双平台输入验证，关键页面原型 | 已确认需求与技术栈 |
| 1 | 工程和桌面基础 | 可启动工程、导航、存储基础、托盘与窗口生命周期 | 阶段 0 相关技术决策确认 |
| 2 | 词库与生词业务 | 合并词库、补充管理、文本添加、生词查看删除 | 阶段 1 |
| 3 | 普通与生词练习 | 输入反馈、分组覆盖复习、进度、统计与结果 | 阶段 2 |
| 4 | 设置和文件交换闭环 | 配置生效、双类 CSV 导入导出、跨窗口与活动会话同步 | 阶段 3 |
| 5 | 下落消除游戏 | 三档难度、循环目标、悬停提示和成绩 | 阶段 4 |
| 6 | 双平台整体验收 | macOS/Windows 10 安装包及验收记录 | 阶段 5 |

## 3. 阶段 0：技术设计与高风险验证

执行范围更新：Windows 10 实机验证经用户明确延期，不阻塞当前开发；不宣称 Windows 兼容性实测通过。交付与实际结果见 [阶段报告](../validation/phase0-report.md)。

目标：解决影响实现的技术不确定性，避免先写业务再重做输入、数据或窗口架构。

任务：

- 核实目标 macOS 最低版本、芯片架构及 Windows 10 测试环境，记录可实际验证的系统与输入法；未确认的支持范围不自行宣称。
- 查阅官方资料选择兼容目标系统的依赖版本与构建打包方案，记录 Windows 10 兼容依据，不默认最新版一定可用。
- 定义主进程、预加载、渲染职责，明确文件访问和持久数据写入边界、类型化通信、错误返回及跨窗口通知方式。
- 设计词条组合唯一性与分类来源、按课程文字保存的熟练记录、覆盖记录、补位轮转位置、设置及活动会话的数据结构。
- 定义持久化与内存会话边界：保存学习进度，但重启不恢复未结束的一局；设计修改、删除、合并的完整变更和失败处理。
- 设计输入判定、计时和会话状态流转，明确输入法候选操作、最终提交、直接空格、粘贴和暂停清除组合输入的处理。
- 用最小验证原型在 macOS 与 Windows 10 检查真实输入法，不以模拟事件替代全部输入验证；候选窗口的交互不能被误当应用失焦或重复提交。
- 检查内置 CSV 的结构、编码长度、重复及分类异常，保留原数据，只报告异常，不擅自纠码。
- 形成练习对齐反馈、托盘添加/结果页、设置及游戏的关键页面原型；记录窗口尺寸、罕见字显示、长词组布局和三档游戏参数的验证结果。

交付：更新架构概览，按需要新增数据结构、接口和决策文档；记录输入验证矩阵、数据检查结果及原型结论。

验收与进入条件：

- 关键存储、进程边界、接口及状态流转有明确约定；重要决策已确认，未确定项有影响范围。
- 真实输入法验证可区分最终提交与选字按键，能覆盖完整词组、空格跳过、游戏空格忽略、粘贴拦截和暂停取消输入。
- 目标系统及依赖版本兼容性有证据；两平台无法验证的项目明确阻塞对应兼容性结论，不能算通过。
- 原型参数不改变已确认业务规则；若发现需求冲突，先报告再确认，不静默改需求。

## 4. 阶段 1：工程与桌面基础

任务：

- 按已确认设计初始化 Electron、Vue 3、TypeScript 工程，配置开发、类型检查、构建及必要测试命令。
- 建立主窗口导航与各页面入口、统一错误反馈，以及主窗口与托盘窗口通信基础。
- 实现用户数据目录、设置和学习数据的初始化、持久化读写；加载内置资源与用户数据分离。
- 实现托盘打开主窗口/文本窗口、关闭主窗口收到托盘、显式退出入口与生命周期处理。
- 提供未开始、运行、暂停、结束状态的公共会话接口供后续功能接入。

验收：

- 双平台可启动开发版本并构建最小安装包，打包后可读取内置词库、写入用户数据目录。
- 内置 CSV 未被改写；重启可恢复测试设置及持久数据，写入失败有明确反馈。
- 关闭主窗口不退出，托盘可恢复窗口及显式退出；不会误创建多个互不一致的窗口状态。
- 类型检查、构建及存储/生命周期基础检查通过并有实际结果记录。

## 5. 阶段 2：词库与生词业务

依据：[生词添加](../requirements/vocabulary-addition.md)、[补充词库](../requirements/supplemental-dictionary.md)。

任务：

- 读取并索引五类内置词库，合并用户补充数据；统一按文字与编码去重，同时保留有效分类来源及全部不同编码。
- 实现补充词库增改、单条/批量删除、校验、重复合并；不修改内置文件。
- 实现最长词组优先、单字兜底、分隔处理及未知内容反馈。
- 实现托盘和主页面粘贴后手动添加，添加后仅展示本次新增文字及编码；继续添加进入下一批输入。
- 实现生词聚合查看、编码级及文字级删除，补充词条变更同步生词编码；新增补充条目不自动加入生词本。
- 实现完整变更后的通知接口，阶段 3/5 再接入活动练习和游戏的变更处理。

验收：

- 用重叠词、词组内部单字、未知字、标点换行、同字多码、重复文本构造可核对的匹配结果。
- 重复添加不新增组合或重置学习记录；结果列表排除已有组合，文字已有但新编码加入时仅显示新编码。
- 改码自动替换已有生词旧组合，重复新组合合并；删码保留其他有效来源，完整变更不触发中途误删。
- 重启后生词与补充数据一致；空结果、格式错误、存储失败可理解且不显示虚假成功。

## 6. 阶段 3：普通练习与生词专项练习

依据：[练习需求](../requirements/practice.md)、[会话规则](../requirements/settings-and-session.md)。

任务：

- 实现课程和时长选择、3 秒倒计时、文字提交判定、正误对齐反馈及错误编码提示；生词题显示全部对应编码。
- 实现与展示数量分离的练习组、自适应排版、每轮打乱、熟练后下一轮逐题替换。
- 实现按课程累计 4 新题/1 复习补位、类别不足互补、复习排序与重新计数、覆盖及熟练展示。
- 实现本次计时、题数/字数统计、到时或主动结束结果，防止暂停、取消题和重复事件污染统计。
- 持久化各课程学习进度和练习组；实现主动/自动暂停、恢复、离页保留及重启不恢复一局现场。
- 接入词库和生词删除修改：移除失效题、取消当前题不计错、下一轮补位、清除对应课程记录、保留已完成统计。

验收：

- 真实输入法选字不重复跳题；完整词组一次判定，单字和跨题拼接不累积，粘贴无作答副作用。
- 用可控时间和题序验证连续正确阈值、错误归零、累计补位、复习顺序、课程独立进度及少量内容缩组。
- 题目显示但未作答不算覆盖，错误/跳过算覆盖；无提交成绩和暂停时间扣除符合口径。
- 词库变更、切页、最小化、倒计时/结束边界不误判；重启恢复学习进度而非一局剩余时间。

## 7. 阶段 4：设置、CSV 与跨窗口闭环

依据：[数据交换](../requirements/data-exchange.md)、[配置与会话](../requirements/settings-and-session.md)。

任务：

- 完成组大小、阈值设置、时长与难度上次选择记忆；下次开局生效，按约定扩缩组和处理阈值。
- 实现两类 CSV 的系统文件选择/保存、字段与 UTF-8 校验、预解析、行级处理及结果反馈。
- 实现文字与编码去重、重复分类保留本机/首个有效值、严格生词词库匹配、文件导入不携带学习进度。
- 联调从补充词库迁移到生词本、主窗口与托盘添加同步、暂停中修改设置与词库等完整流程。
- 完成切换课程/重新开始/退出的确认、关闭到托盘及用户取消操作的状态保持。

验收：

- 往返导出导入、重复导入、相同文字不同编码及跨分类冲突结果可核对，不丢本地独有条目或覆盖学习进度。
- 缺列或无法解析整份不写入，个别非法行只跳过该行；空行/额外列处理、BOM 和取消文件选择符合约定。
- 未先导入补充词库的生词行被跳过，先导入后可识别；既有内置资源不被改写。
- 修改设置不改变暂停中的一局，下次开局正确生效；退出确认取消后现场保持，确认后重启仅恢复学习进度。

## 8. 阶段 5：下落自由消除游戏

依据：[游戏需求](../requirements/typing-game.md)。

任务：

- 接入五类及生词课程，独立随机选题，屏幕同文字去重，消除补题和落底循环。
- 实现完整目标匹配、错误清空、空格忽略、悬停编码与单目标暂停、整局暂停恢复。
- 按阶段 0 原型参数实现三档数量与速度，验证长词组、少量题目、重入与目标避让；局内不加速。
- 实现消除题数、正确字数、错误提交、正确率及速度，不增加积分或普通练习熟练记录。
- 接入词库变更、窗口失焦、切页、结束和退出的统一规则。

验收：

- 落底循环不计漏题或错误，匹配只消除一个完整目标，拼接目标提交计一次错误，粘贴不改变成绩。
- 悬停仅冻结该目标，整局暂停冻结全部目标和计时；恢复位置一致，结束后不会继续作答或补题。
- 游戏前后普通练习覆盖、连续正确次数和练习组不变。
- 空课程、课程不足、词库目标失效、长词组及三档难度均有运行验证记录。

## 9. 阶段 6：双平台打包与整体验收

任务：

- 对 macOS 和 Windows 10 的目标系统、架构及输入法执行回归，记录系统版本、包版本和实际结果。
- 验证从安装、启动、离线练习到托盘积累、生词专项、补充管理、CSV 迁移与游戏的完整流程。
- 验证打包资源路径、普通权限写入用户数据、重启保存及退出行为，检查内置词库未改变。
- 检查罕见字字体、长词组排版、窗口缩放和游戏提示；记录大词库加载、文本识别及游戏运行表现，若不满足交互需求则针对性优化。
- 整理安装包、使用说明、已知限制、测试结果和剩余问题；签名或分发条件未具备时单独说明，不宣称已签名发布。

验收：

- 两平台实际安装运行及核心场景均有结果记录；仅构建成功不算目标平台验收通过。
- 未通过的关键数据一致性、输入或平台兼容问题已修复并复验，不能通过删除检查或降低要求掩盖。
- 无法验证的系统或输入法明确标为未验证；影响已承诺目标平台时不得宣布整体完成。
- 项目状态、模块行为、已知问题和使用说明与实际实现一致。

## 10. 持续维护

- 每阶段开始前检查任务、依赖、设计和现有实现；完成后记录实际改动、验证命令/环境/结果及未解决事项。
- 核心规则用确定性业务测试验证，输入法、托盘、文件对话框和安装包补充真实平台检查；模拟测试不能代替操作系统集成验证。
- 发现需求冲突先报告，重要技术变更按项目规则确认；不借执行计划扩充已排除功能。
- 阶段状态仅在真实完成后更新。计划整体完成后，按文档管理规范将有效行为并入模块文档并移除已完成计划。
