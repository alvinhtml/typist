# 游戏概览与需求边界

## 目标
将 Typist 现有「下落消除游戏」原位升级为「太空打字防御战」，兼顾五笔 86 编码练习与街机射击乐趣（两者同等重要）。游戏继续离线运行。

## 已确认
- 平台/技术基线：Electron 44.2.0、Vue 3、TypeScript、Vite；Electron 主进程经 Preload/IPC 管理持久化，渲染进程保持沙箱与上下文隔离。
- 不新建并列游戏模式；保留现有游戏入口，替换其游戏画面与玩法。
- 完全俯视角，半写实科幻军事美术；玩家为**固定位置的飞船**，朝目标转向并射击，不用方向键移动。
- 敌人为不同型号的飞船；敌机核心上方叠加清晰、始终正向的全息汉字/词组；文本和美术资源分层。
- 玩家自主选择任意敌机进行编码攻击，不设预选「当前目标」或强制锁定目标。
- 单字和词组完全同等：每个目标关联一条最长四码的五笔 86 编码；词组仅是显示内容不同。
- 沿用现有输入提交：四码自动提交；不足四码以空格提交。编码成功后一次攻击；多血量目标重复提交同一编码。
- 普通敌机 1/2/3 HP；每次普通攻击扣 1 HP。高速奖励敌机击毁后获得穿甲弹；有弹药时，攻击**剩余 2–3 HP**目标自动消耗一发并一击击毁；剩余 1 HP 不消耗。
- 游戏需提供弹道飞行、命中火花、装甲受损、爆炸和飞船转向等反馈；视觉动画不得阻塞快速输入。
- 保留原有三档难度、计时、暂停、独立成绩，以及词库和编码判定能力。

## 设计建议，非最终确认
- 第一版普通敌机以抵达底部撞击防线为主要威胁；不增加需要躲避的敌方弹幕。
- 奖励敌机逃脱不扣耐久；特殊弹药库存上限 3 发。
- 防线初始耐久 10；普通/装甲/重型突破分别扣 1/2/3 点。
- 以 5 分钟波次作为平衡参考，但保留现有时长选项；得分按机型及连击倍率计算。

## 必须先确认或保留策略接口的规则
1. 同编码的多个敌机：是否按距离防线最近优先，还是其他规则。
2. 编码前缀冲突：短码 + 空格提交与四码自动提交的缓冲、错误恢复细节，应先以现有行为为准。
3. 同一个字词是否可能对应多条合法编码，以及复用现有词库的方式。
4. 敌机突破防线与伤害值、奖励机逃脱处理。
5. 游戏结束条件（时间到、耐久归零）、暂停期间计时/动画行为及旧成绩兼容。
6. 玩家飞船旋转幅度、自动瞄准视觉与高速输入时多发子弹的表现。

## 不在本次范围
- 自动交易、联网游戏、排行榜服务、多人联机、角色养成、复杂技能树、自由移动、Boss 关卡、全新游戏引擎迁移。
- 重构非游戏业务；无必要地改变 SQLite 表结构或 IPC API。

## 质量目标
- 不改变既有五笔练习和词库业务；离线可用。
- 输入处理与视觉渲染分离；连续输入不能等待上一颗子弹命中。
- 文字清晰优先于特效；同屏多目标、词组长短变化和高 DPI 下均应可读。
- 测试覆盖关键规则与原有回归路径。
