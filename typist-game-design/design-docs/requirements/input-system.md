# 五笔 86 输入与目标选择

## 核心原则（已确认）
- **直接接收键盘字母并判定五笔编码**，不是使用中文输入法逐字提交。
- 四码自动提交；1–3 码由空格提交。其他键位处理、退格和错误恢复须复用当前游戏的实际实现。
- 字与词完全一致：编码最长四位。例：「企业」编码 `whog`，提交后算一次攻击。
- 玩家无须预先选择目标；输入合法目标编码即攻击。
- 编码命中时飞船向该目标转向并发射；射击/命中特效不得阻塞后续输入。

## 匹配策略接口（需代码审查后确认）
```ts
interface TypingTarget {
  id: string;
  text: string;
  codes: readonly string[];
  hp: number;
  maxHp: number;
  positionY: number;
}

interface TargetSelectionStrategy {
  selectTarget(submittedCode: string, targets: readonly TypingTarget[]): TypingTarget | null;
}
```
此为概念接口，非要求直接替换现有类型。代码审查时应明确：
- 一条文字多编码的合法性与词库数据结构；
- 多个敌机同编码时的排序/优先级；
- 已被判定击毁但爆炸动画尚未结束的敌机是否仍参与匹配（建议不参与）；
- 输入缓冲区清空时机、四码自动提交和短码空格提交是否与现有游戏一致；
- 当前无匹配目标时如何计错，以及连续输入/暂停时如何处理。

## 不要做的事情
- 不用「先输入第一个汉字再锁定词组」机制。
- 不将词组分拆成多个字符目标。
- 不强制显示「当前目标」，也不强制将输入与单个预选敌机绑定。
- 不把敌机的完整五笔编码默认显示在战场上（可保留现有辅助提示能力，但是否启用待确认）。

## 建议测试场景
1. 单字四码自动提交，单字短码空格提交。
2. 词组四码 `whog` 提交并发射；多血量词组重复提交。
3. 输入不匹配任何存活敌机的编码。
4. 多敌机同编码、同字不同编码、编码前缀冲突。
5. 100ms 级连续提交时仍能接受新输入，不依赖动画完成。
6. 暂停、恢复、计时结束、敌机死亡过渡期间的输入行为。
7. 与分级练习编码模块复用后，其他练习页面无回归。
