# Codex 分阶段实施计划

## 第 0 阶段：只读代码审查（必须先做）
1. 检查 `design-docs/requirements/typing-game.md`、`design-docs/architecture/overview.md`、游戏相关 Vue/TS、编码输入/词库、设置与成绩模块、测试。
2. 列出当前游戏模块、可复用能力、必须修改的文件、测试命令和现有行为。
3. 标明文档与代码不一致之处，**以代码为准**；不影响其他练习功能。
4. 形成待确认问题清单（同码冲突、短码前缀、耐久、逃脱、结算、成绩兼容）。
5. 提交改造方案及小步提交顺序；未经确认不得擅自修改未定规则。

## 第 1 阶段：可玩的逻辑纵向切片
- 复用现有五笔编码提交机制，建立敌机状态、自由选敌、HP、伤害、死亡与成绩的纯逻辑模块。
- 使用占位飞船和简单弹道验证：输入编码 → 目标受击 → 敌机消灭。
- 覆盖单字/词组、四码/短码、多 HP、连续输入与同码边界的单元测试。
- 保留现有游戏设置、暂停、计时及结算流程。

## 第 2 阶段：战场渲染
- 将游戏内容区升级为俯视战场；Vue 外围 HUD + 可评估的 Canvas 2D 渲染层。
- 实现固定飞船、自动转向、敌机下落、动态文字核心、HP 格、弹道与爆炸占位效果。
- 实现素材预加载、窗口缩放、资源回退、暂停/恢复与销毁清理。

## 第 3 阶段：奖励与难度
- 接入高速奖励机、智能穿甲弹、库存、难度参数、敌机生成策略、防线/结束规则（待确认后实施）。
- 处理多目标同码、死亡中的敌机、连续多次发射、同时突破等边界。
- 完善分数/连击/速度/准确率统计及成绩持久化兼容。

## 第 4 阶段：正式素材与打击反馈
- 先确认 5 款飞船的统一视觉设定，再接入透明 PNG。
- 增加独立全息文字、命中火花、受损、轻/重爆炸、普通/穿甲弹和太空背景。
- 逐步调节粒子量、遮挡、动画时间与性能，不影响输入响应。

## 第 5 阶段：验收与回归
- 执行项目实际存在的测试、TypeScript 检查、构建、Electron 桌面冒烟。
- 验证离线运行、macOS/Windows 构建兼容；Windows 实机验收如缺设备则明确标记未完成。
- 回归分级练习、生词本、补充词库、CSV、设置、托盘和学习进度。
- 试玩不同编码长度、词组、同屏密度、低/高难度、不同窗口尺寸。

## 交付纪律
- 每阶段提交变更摘要、涉及文件、测试结果、未解决问题与下一阶段任务。
- 不删除或覆盖用户数据；数据库变更必须有迁移/回退方案。
- 不引入新游戏引擎、远程服务或不必要的大型依赖。
- 任何规则不清楚时先建立策略接口/配置占位并提出问题，不得凭空决定。
