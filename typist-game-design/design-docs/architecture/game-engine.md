# 游戏架构与现有项目集成建议

> 本文仅为架构建议，**尚未检查 Typist 源代码**；不得据此假定现有目录/类名。

## 集成原则
- 保留 Electron 主进程、Preload 的 `window.typist` IPC 边界与安全设置；尽量在现有渲染进程内实现战斗。
- 复用现有五笔编码判定、出题、计时、暂停、难度配置和成绩持久化；先建立实际模块清单，再决定扩展点。
- 游戏逻辑采用纯 TypeScript 模块，避免依赖 Canvas、DOM 或 Vue 组件，便于单元测试。
- 推荐 Vue 负责外部 UI 与状态交互；Canvas 2D 负责战场精灵、弹道、爆炸、文字投影。若现有渲染方式已足够，需先做性能/可维护性评估再迁移。

## 建议模块边界
```text
现有 Typist UI / 游戏入口
  ├─ 游戏会话控制（计时/暂停/结算/难度）
  ├─ 输入适配（复用现有四码自动、短码空格）
  ├─ 目标选择策略（同编码冲突待确认）
  ├─ 战斗规则（敌机/HP/特殊弹药/防线/得分）
  ├─ 事件流（提交成功、开火、命中、击毁、突破）
  ├─ 视觉渲染（飞船/文字/弹道/特效/HUD）
  └─ 结果适配（复用现有成绩存储）
```

## 更新与渲染
- 使用固定或受控步长更新游戏状态，渲染根据状态与动画时间绘制。
- 每次有效编码提交同步生成攻击意图，目标与伤害按明确顺序判定；动画播放是非阻塞事件消费。
- 同一目标在飞行中的多颗子弹、被击毁目标的后续攻击、奖励发放时机必须有一致规则和测试。
- 使用 `requestAnimationFrame` 或既有时钟；暂停/窗口隐藏时限制时间跳变；资源在组件卸载时释放。
- 图像纹理预加载与缓存，避免每帧解码；按设备像素比缩放并限制最大渲染成本。

## 数据兼容
- 先确认现有游戏成绩表/字段和设置键，优先兼容读取；如确需 schema 迁移，增加显式版本与回归测试。
- 课程学习进度与游戏成绩保持隔离；不触碰内置只读 CSV 与用户补充词库语义。
- 禁止为视觉特效引入联网依赖或更改 Electron 沙箱安全配置。

## 测试层次
- 纯逻辑单测：目标选择、四码/短码、伤害与弹药、死亡、突破、计分、暂停、计时。
- 组件/渲染测试：文字正向、资源加载失败回退、缩放与 HUD 状态。
- 桌面冒烟：真实 Electron 启动、离线游戏、暂停恢复、结算、重启后成绩。
- 全量回归：分级练习、生词本、补充词库、CSV 导入导出、托盘与设置。
